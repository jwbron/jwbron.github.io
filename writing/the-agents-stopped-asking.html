The agents stopped asking

My agents slowly stopped bringing me decisions, and every run still looked fine.

A few months into running egg on its own codebase, I noticed it had gotten quiet.

egg is built so that agents bring me the decisions that are mine to make, like scope, tradeoffs, and anything a reasonable person would want a say in. Early on, a run would usually turn up a handful of those before any work started, often around eight. Over the next couple of months that number drifted toward zero. Runs sailed through planning with nothing for me to weigh in on.

It would have been easy to take that as good news. Maybe the tasks were simpler, or the agents had gotten better at handling the small stuff themselves. But when I read the reasoning on one of those quiet runs, it had a familiar shape. The agent had decided that every open question was an implementation detail, which made it the agent's call, and moved on. For that particular task it was a defensible read. It was also exactly what a system that had learned to stop asking would look like from the outside.

Two good changes that added up to a bad one

When I went back through the history, the drop lined up with two changes I'd made, and both had fixed real problems.

The first narrowed what agents were supposed to ask about during planning. Questions about how to break up the work belonged later, so I told them to leave those out. They took that and ran with it. Anything that felt like implementation became something not to ask about, and that swallowed real questions about scope and judgment along with it.

The second gave agents a clear way to say "nothing here needs a decision." The idea was to make the empty case explicit, so I could confirm it instead of guessing. In practice it also became the easy way out. Writing up a good question, with the options and a recommendation, takes real work. Writing one sentence that says there's nothing to ask doesn't.

There was a third problem underneath both. When an agent thought a question was better asked later, it would say the next phase would pick it up. So I checked whether it did, and it almost never did. Nothing in the next phase was looking for those deferred questions, so they just vanished.

Making "nothing to decide" cost something

I didn't undo either change. Instead I made "nothing to decide" something an agent has to back up.

An agent can't just say there are no decisions anymore. It has to list the questions it actually thought about and say, for each one, why it isn't mine to make or why it should wait. That list is what I see when I confirm, so I'm checking specific reasoning instead of waving through a paragraph. And anything an agent puts off now travels with the work into the next phase, which has to either bring it to me or explicitly set it aside. Putting something off became a handoff instead of a way for it to disappear.

The questions came back.

What I took from it

Agents find the path of least resistance, and a quiet system isn't the same as a healthy one. Nothing about this ever broke. Every run finished, and every run looked fine. The only sign was that I was being asked less, which is exactly the kind of signal that's easy to mistake for progress.

This applies well beyond code. Picture an agent pulling together research for a legal team. The dangerous moment isn't when it gets something obviously wrong, because someone will catch that. It's when it quietly settles a question that should have gone to a partner, because asking felt like extra work and nothing stopped it from deciding on its own. The fix looks the same there. Make the agent show what it considered, and make sure the questions it puts off actually land somewhere.

When your agents get quiet, find out why before you celebrate.
